# Image Splitter v1.0

画像を左右・上下・グリッドに分割する、スマートフォン向けの画像編集Webアプリです。React / TypeScript / Vite / Canvas / JSZipで実装しています。バックエンド、アカウント、外部APIは不要です。

公開アプリ：**[Image Splitter](https://ohno-nori.github.io/image-splitter/)**

ソース：[ohno-nori/image-splitter](https://github.com/ohno-nori/image-splitter)。GitHub Pagesは `main` ブランチの `docs/` を配信します。画像の処理は公開版でも端末内で完結します。

## ローカルで使う

Node.js **24 LTS推奨**。対応条件は `package.json` の `engines` を参照してください（Node 22.12以上の22系、24系、26以上）。検証環境はWindows / Node 24.13.0です。

このフォルダーでターミナルを開いて実行します。

```bash
npm install
npm run dev
```

表示されたURL（通常 `http://127.0.0.1:5173/`）をブラウザで開きます。終了はターミナルで `Ctrl+C`。ポートが使用中の場合はViteが別ポートを選ぶことがあります。

依存関係をlockファイルどおりに再現する場合は `npm ci` を利用できます。初回のライブラリ取得にはインターネット接続が必要です。

### 本番ビルド・PWA確認

```bash
npm run test
npm run build
npm run preview
```

`dist/` に本番成果物を生成します。プレビューURLは通常 `http://127.0.0.1:4173/` です。**PWAのオフライン動作は `dev` ではなく `build` → `preview` で確認してください。** HTMLのファイルを直接ダブルクリックする起動方法には対応しません。

## 使い方

1. 「画像を選択」でPNG・JPEG・WebPを読み込みます。スマートフォンの写真ライブラリ・ファイルアプリ、PCのドラッグ＆ドロップにも対応します。
2. 左右（左から右）・上下（上から下）・グリッド（左上から横方向、次の行）を選びます。
3. 枚数を増減ボタン、または数値入力で設定します。左右・上下は2〜20枚。グリッドは各方向1〜20、合計100枚以内です。
4. 必要に応じて比率・配置・保存形式を変更します。
5. 「分割画像を確認」で各画像を確認し、個別保存するか、「ZIPで一括保存」を選びます。

ファイル名、向きを反映した幅・高さ、アスペクト比、ファイルサイズ、1枚の出力寸法、出力枚数を表示します。EXIF Orientationはブラウザの画像デコーダーで反映します。元ファイルは変更しません。

### 原寸で分割（初期設定）

拡大・縮小・トリミングをせず、元画像を整数座標で分割します。配置・倍率・背景・出力幅の設定は表示されません。1001pxを3分割すると333 / 334 / 334pxになります。分割境界は `floor(i × 元サイズ / 分割数)` で計算し、各方向の差は最大1pxです。

**可逆なPNGで保存すれば、ブラウザでデコードした画像のピクセルを欠落・重複なく再結合できます。** JPEG・通常のWebP保存は非可逆圧縮です。原ファイルの圧縮バイト列やメタデータを保存する機能ではありません。

### アスペクト比指定

3:4 / 4:5 / 1:1 / 16:9 / 9:16 / 3:2 / 2:3、またはカスタム比率に対応します。比率は**1枚の出力画像**に適用します。例えば3:4を横3枚にすると、全体は9:4です。

全体の出力サイズと画像配置を確定し、**一度描画した全体キャンバスを整数座標で切り分けます**。タイルを個別にリサイズ・トリミングしないため、境界の構図がつながります。

カスタムの横・縦は0.001〜10000、小数点以下3桁までです。入力を整数比に約分し、その整数倍でタイル寸法を決めます。正確な比率を保てない入力はエラーにし、近似比率への置き換えは行いません。

- **全体表示**：画像全体を収める倍率にして中央配置。
- **余白なし**：全体キャンバスを覆う最小倍率にして中央配置。
- 両ボタンは自動調整のショートカットです。その後も自由に移動・拡大縮小できます。
- 背景は白・黒・透明・カスタムカラー。PNGとWebPは透明を保持できます。JPEGでは透明部分を白にし、その旨を画面に表示します。

### 操作

| 操作                                           | 動作                             |
| ---------------------------------------------- | -------------------------------- |
| 1本指／マウスでドラッグ                        | 画像を移動                       |
| 2本指ピンチ                                    | ピンチの中心を基準に拡大縮小     |
| 倍率スライダー                                 | キャンバスの中央を基準に拡大縮小 |
| マウスホイール                                 | カーソルを基準に拡大縮小         |
| ダブルタップ／ダブルクリック／中央に戻すボタン | 倍率を保って中央へ戻す           |
| 編集領域にフォーカスして矢印キー               | 少しずつ移動                     |
| プレビュー右上の拡大ボタン                     | 大きな編集ダイアログを開く       |
| 個別プレビューで左右スワイプ／前後ボタン       | 前後の画像へ切り替え             |

比率指定の画像操作エリアのみページスクロールを抑止します。その他の場所では通常どおりスクロールできます。倍率と位置は画像を選び直すと初期化され、設定変更だけでは不用意にリセットしません。

### 出力サイズ

- 原寸：元の解像度を維持。サイズ指定は使用しません。
- 比率指定の自動：全体の幅・高さが元画像以下になる最大の整数倍率を採用し、不要なアップスケーリングを避けます。
- 比率指定のサイズ指定：1枚の横幅を指定。1080 / 1440 / 2048pxまたは任意の整数。比率の最小整数単位に合わせて最も近い有効幅へ調整し、結果を表示します。
- 自動で比率の最小整数単位すら確保できない画像では、比率を簡単にするかサイズ指定を利用してください。

### 保存

PNG / JPEG / WebPに対応。JPEG・WebPは品質10〜100%、初期値94%です。

- 個別保存：`元画像名_01.png` のような連番。
- ZIP：`元画像名_split.zip`。番号はプレビューの順番と一致。
- ファイル名の不正文字を除去。処理中の進捗を表示し、二重実行を防ぎます。
- 作成後の「もう一度保存」で再ダウンロードできます。
- 対応環境では「共有・ファイルに保存」も表示します。iPhoneでダウンロードが見つからない場合は、共有メニューから「ファイルに保存」を利用してください。写真ライブラリへの直接保存は保証しません。
- ブラウザからOSへの保存を依頼しますが、OS側でキャンセルされたか、最終的に保存されたかはブラウザから完全には判定できません。

## PWA・オフライン

Manifest、Service Worker、192 / 512pxのPNGアイコン、maskableアイコン、Apple Touch Icon、standalone設定を同梱しています。外部画像・フォントCDNには依存しません。

1. `npm run build` → `npm run preview` でアプリを一度読み込みます。
2. 「オフライン準備完了」を確認します。
3. オフラインにして再読み込みし、端末の画像を選んで分割できます。

インストールにはHTTPSまたはlocalhostが必要です。iPhoneではSafariの共有メニュー → 「ホーム画面に追加」。PCやAndroidの対応ブラウザではインストールメニューを使います。

アプリ本体をWorkboxで事前キャッシュし、新バージョンは利用者が更新ボタンを押すまで待機します。書き出し・読み込み中は更新できません。更新すると画像は選び直しになります。ブラウザの保存領域が削除された場合は、再度オンラインで読み込みが必要です。

PCのlocalhostはスマートフォン自身のlocalhostではありません。同じWi-Fiで `--host 0.0.0.0` を使う場合も、通常のHTTP LAN配信ではPWA機能が制限されます。実機PWA確認には適切なローカルHTTPS環境などを別途用意してください。

## 設定とプライバシー

分割方式・数・出力方式・比率・形式・品質・背景・解像度・テーマを `localStorage` の `splitter-settings` に保存します。不正な保存設定は項目ごとに安全な初期値へ戻します。端末設定に追従するテーマと明暗の手動指定に対応します。

画像本体、画像固有の位置・倍率は永続保存しません。再起動・再読み込みで画像は失われます。画像アップロード、アクセス解析、外部APIへの通信処理はありません。Service Workerが保存するのはアプリの静的ファイルだけです。保存設定やキャッシュはブラウザのサイトデータ削除で消せます。

## 制限・未検証事項

- 入力は64MiB以内、2,400万画素以内、各辺16,384px以内。描画前にヘッダーの寸法を検査します。出力キャンバスも同じ画素数・辺長制限です。
- ZIP内の圧縮済み画像の合計が128MiBを超えると処理を中止します。タイルは順番に生成し、一時Canvasを解放します。JSZipは最終ZIPをメモリ上で構築するため、ディスクへ完全にストリーミングする方式ではありません。
- 端末によっては制限値以下でもメモリ不足になります。30枚以上または1,200万画素超の出力には警告を表示します。タブ自体がOSに終了された場合の復旧はできません。
- カスタム比率によっては正確な整数寸法が大きくなり、制限により出力できません。簡単な比率へ変更してください。
- HEIC・GIF・SVGの入力、アニメーション出力には非対応です。アニメーションPNG/WebPはブラウザがデコードする静止フレームを扱います。
- 色管理、ICC、EXIFなどはブラウザのCanvas仕様に依存し、元メタデータは保持しません。完全透明ピクセルの不可視RGBや広色域・高ビット深度の完全な保持は保証しません。
- WebPエンコード非対応ブラウザでは日本語エラーを出し、PNGへの切り替えを案内します。
- **iPhone Safari実機、ホーム画面PWAでのOS共有／保存、Android実機は未検証です。** スマホ幅・タッチはChromiumのエミュレーション検証であり、Safari実機の検証ではありません。
- Service Workerの生成・オフライン再読み込みは自動検証済みですが、実機のホーム画面インストールや旧版から新版へのOSを含む更新体験は未検証です。

## テスト

```bash
npm run test
npm run build
npm run test:e2e
npm run test:subpath
```

E2Eはインストール済みGoogle Chromeを標準使用し、PCとiPhone 13相当の画面／タッチ環境で実行します。Chromeがない場合は、Microsoft Edgeを指定できます。

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
Remove-Item Env:PLAYWRIGHT_CHANNEL
```

`test:subpath` は `/image-splitter-check/` という仮のベースパスで `dist-subpath/` をビルドし、ポート4174の一時サーバーでManifest・キャッシュ・オフラインZIPを確認して終了します。E2Eはポート4173を使います。いずれも外部公開はしません。

検証結果は [VALIDATION.md](VALIDATION.md) を参照。E2EのHTMLレポートは `playwright-report/index.html`、スクリーンショットは `test-artifacts/` に出力します。

## 構成・計算の責務

```text
src/
  App.tsx                  状態・各設定・読み込みと保存の進行管理
  components/Editor.tsx    Canvasプレビュー・Pointer Events・ピンチ
  components/Dialog.tsx    モーダル・フォーカス・スクロール制御
  lib/model.ts             型・設定検証・整数分割・比率・配置計算
  lib/image.ts             ヘッダー検査・読み込み・Canvas描画・エンコード
  lib/export.ts            タイル順次書き出し・ZIP・ダウンロード
  styles.css               レスポンシブ・テーマ・セーフエリア
tests/                     PlaywrightのUI・保存・ピクセル検証
scripts/                   アイコン生成・サブパス検証
public/                    ローカルアイコン・.nojekyll
dist/                      本番ビルド（再生成可能）
```

配置はキャンバス中央からの相対オフセットと、全体表示を1とする倍率で管理します。プレビューと出力は同じ `imageRect` / `drawScene` を使います。画面の解像度や出力サイズが変わっても構図を維持します。

アイコンを変更した場合は `public/icon.svg` を編集し `npm run icons` を実行します。コード整形は `npx prettier --write src tests scripts *.ts *.json index.html`。`overrides` はビルド用の間接依存の既知の問題への対策で、Workboxを含む実ビルドを検証しています。依存更新時は単体・本番・PWAテストを再実行してください。

## GitHub Pagesへの更新手順

公開先は https://ohno-nori.github.io/image-splitter/ です。GitHubの Settings → Pages は「Deploy from a branch」、`main` / `/docs` を使用します。

1. ソースを変更し `npm run test` と必要なブラウザテストを実行します。
2. `npm run build:pages` で `/image-splitter/` 用の成果物を `docs/` に生成します。
3. ソースと `docs/` を確認し、公開する変更をGitHubの `main` ブランチへコミット・pushします。
4. GitHub Pagesのデプロイ完了後、公開URLとPWA更新を確認します。

`docs/` は生成物ですがPages配信のためGit管理対象です。`.nojekyll` とローカルアイコンも含みます。独自の自動公開GitHub Actionsワークフローは同梱していません。Pages自身のビルド・デプロイ処理はGitHubが管理します。

リポジトリ名や公開パスを変更する場合は `scripts/build-pages.mjs` のベースパスとREADMEのURLを変更してください。通常のローカルビルドは引き続き `npm run build` で `dist/` に出力されます。
